Graph → Cities & roads (Nodes + Edges)

3.2 Coding Patterns (Mastering the Logic Behind Problems)
“Stop solving 1000 problems. Start mastering 16 patterns.”
“Don’t memorize problems. Recognize patterns.”

This will be the single most important thing in this whole journey. The earlier you realise this the better the 90 days journey would be.
Why This Matters
Most coding interview problems are just variations of a few repeatable logic patterns. Once you identify and internalize these, you’ll solve any problem faster — not by memorizing, but by recognizing.

How to Approach
Go in order — Beginner → Intermediate → Advanced.
For every pattern, first read or watch to understand the logic, then solve 3–5 problems.
Maintain a small Pattern Tracker (Pattern name | Example problems | Key insight).
Revisit old patterns regularly — repetition cements recall.

Suggested Learning Order
Start with Beginner GitHub + 15 Patterns video to build familiarity.
Practice 3–5 problems for each pattern (e.g. Sliding Window, Two Pointers, BFS/DFS).
Move to Intermediate — focus on real interview-style problems and pattern variations.
Finish with Advanced — deep dive into dynamic programming, graph algorithms, and complex recursion.

3.3 Brute Force → Optimized Thinking
“Think slow first, then optimize fast.”

Step-by-Step Approach
Start with a brute-force solution — don’t fear O(n²). Clarity first.
Write down what’s repeating — loops, recalculations, unnecessary traversals.
Ask “what if I could store or skip this?” → that’s where data structures and patterns help.
Apply optimization using known approaches:
Hashing / Maps for lookups
Sorting + Two Pointers
Sliding Window for subarrays
Prefix/Suffix logic for accumulative patterns
Binary Search on answers

Part 4: DSA Prerequisites — Before Starting the 90-Day Plan
